# TGA.UI

> Автоответчик и ReAct-агент для Telegram.
>
> *переодически это помогает почуствовать себя нужным (zxc)*

## Возможности

- Автоответы для выбранных контактов.
- Triage-модуль, который решает: ответить, подождать или проигнорировать.
- Два режима генерации: `Ghost` и `Agent`.
- Поиск по локальной истории сообщений и удалённый поиск через tools.
- Загрузка диалогов, контактов и аватаров Telegram.
- Сохранение состояния агента и истории в SQLite.

## Быстрый старт

### 1. Подготовить настройки

Склонируйте репозиторий и создайте файл `TGA.UI/appsettings.json`.
Укажите `ApiId` и `ApiHash`, полученные на [my.telegram.org](https://my.telegram.org).

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore.Database.Command": "Warning"
    }
  },
  "AllowedHosts": "*",
  "Telegram": {
    "ApiId": "ВАШ_API_ID",
    "ApiHash": "ВАШ_API_HASH"
  },
  "ConnectionStrings": {
    "Default": "Data Source=telegram_assistant.db"
  },
  "HistoryLoad": {
    "DefaultMessagesPerDialog": 20,
    "MaxMessagesPerDialog": 100
  }
}
```

### 2. Запустить приложение

1. Подключите стабильный VPN: он заметно влияет на авторизацию в Telegram.
2. Запустите проект `TGA.UI` из IDE или через .NET CLI.
3. Откройте адрес, указанный в консоли приложения. Обычно это `http://localhost:5213`.
4. Перейдите на `/login` и запустите авторизацию.
5. Пройдите подтверждение номера телефона, кода и пароля 2FA, если он включён.
6. После успешного входа нажмите **«Загрузить диалоги»**.

> Логи восстановления сессии и подключения доступны на главной странице приложения.

## Первичная настройка агента

1. Откройте `/llm-settings`, заполните настройки LLM и проверьте соединение.
2. Перейдите на `/contacts` и откройте редактирование нужного контакта.
3. Заполните профиль контакта и включите автоответчик.
4. Выберите режим `Ghost` или `Agent` и при необходимости добавьте инструкции.
5. Попросите контакт отправить несколько сообщений.
6. Подождите примерно 7 секунд после последнего сообщения: сработает debounce и начнётся triage.
7. Если triage выберет `Reply`, агент сгенерирует и отправит ответ.

## Путь сообщения

```text
Telegram Message
       |
       v
1. BUFFERING & DEBOUNCING
   AutoReplyDebounceService
   - накапливает сообщения до DebounceSeconds;
   - может продлить ожидание до MaxWaitExtensions раз.
       |
       v
2. TRIAGE
   TriageService -> LLM Call #1
   - temperature 0.1;
   - контекст профиля контакта, истории и новых сообщений;
   - решение: Reply / Wait / Skip.
       |
       v
3. AGENT EXECUTION (ReAct Loop)
   AgentService -> LLM Call #2...#N
   - системный промпт;
   - история переписки;
   - few-shot примеры для Ghost;
   - триггер-сообщения;
   - результаты tools.
       |
       v
4. PERSISTENCE
   AgentRunStorageService -> SQLite
   - сохраняет состояние между уточнениями;
   - устраняет дубликаты импортированных сообщений.
```

## Состав LLM-запросов

### Triage: LLM Call #1

Лёгкий классификационный запрос с температурой `0.1`.

**System:** решение `reply / wait / skip`.

**User prompt:**

```text
Контакт: DisplayName, Notes, CommunicationStyle, AutoReplyInstructions
Контекст: последние HistoryContextSize сообщений
Триггер: новые сообщения, ожидающие обработки
```

### Agent execution: LLM Call #2 и далее

#### Режим Ghost

- инструкция имитировать стиль пользователя;
- до `GhostStyleExampleCount` собственных сообщений пользователя;
- `profile.Notes`;
- `profile.BehaviorProfile`;
- `profile.AutoReplyInstructions`.

Ориентировочный объём: 300–400 токенов служебного контекста.

#### Режим Agent

- инструкция отвечать как помощник;
- metadata профиля контакта;
- дополнительные инструкции.

Ориентировочный объём: 150–200 токенов служебного контекста.

#### Общие ограничения

- не придумывать факты, даты и события;
- использовать только результаты tools;
- сохранять контекст предыдущих итераций ReAct.

### Структура итераций

На первой итерации:

```text
Последние сообщения переписки:
  [время, автор, текст] x HistoryContextSize

Новые сообщения, на которые нужно отреагировать:
  [триггер-сообщения] x N
```

На следующих итерациях:

```text
Assistant role: предыдущий ответ и tool_calls
Tool role: результаты выполнения инструментов
User role: новая информация, если агент запросил уточнение
```

## Roadmap

### Управление и автоматизация

- Добавить чат для управляющих команд:
  - `/stop`;
  - `/start`;
  - `/response username`;
  - `/search`;
  - `/research`.
- Добавить кнопку **«Ответить агентом»** в чате с учётом текста из поля ввода.
- Добавить интеграцию с Google Calendar.

### Контекст и качество ответов

- Добавить мониторинг token usage из ответов LLM.
- Для больших историй использовать semantic search или summarization.
- Реализовать подбор few-shot примеров для Ghost:
  - фиксированный набор из 5–7 характерных диалогов;
  - динамический подбор 3–5 релевантных примеров через embeddings.
- Разделить блоки промпта, которые сейчас склеены.
- Добавить token streaming или compression для последующих итераций ReAct.

### Tools и производительность

- Добавить timeout и graceful degradation для remote search.
- Ранжировать результаты tools и передавать агенту только наиболее релевантные записи.
- Дополнить `PathHelp` для ввода пути в export-парсере.

### Приватность и события Telegram

- Добавить blacklist контактов, исключающий их сообщения из поиска и обработки.
- Сохранять в БД, на какое сообщение и почему был отправлен ответ.
- Подписаться на события Telegram вроде «выбирает стикер».
- Учесть typing-события в debounce-логике.

### удобства

- добавить огоньки
